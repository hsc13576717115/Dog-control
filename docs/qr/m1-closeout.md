# M1 收尾：故障可观测性与冻结验收

[中文入口](README.md) | [English overview](README_EN.md)

本轮继续 M0—M7 的阶段门槛，先补 M1。这里记录实现和测试范围；最终执行统计见本页末尾及机器可读结果，未列出的测试不得视为通过。

## 控制侧改动

- `control/SampleFreshness.hpp` 统一采样时间检查，拒绝缺失、非有限、过期、未来和倒序时间。允许控制循环重复读取仍在有效期内的同一采样，但不延长其寿命。
- `JointSample` 增加采样时间及有效标志。Gazebo 同步反馈使用物理更新时刻；真实硬件时间仍待驱动提供，不能用读取时刻替代。精确模式仍禁止真机。
- 摆腿位置持续偏离参考 25 mm 超过 80 ms 时中止，固定错误码 35。它表示跟踪受阻，不声称已准确识别碰撞原因，也不能作为已触地证据。
- `FootstepExecutor` 在站立、结束和保持阶段继续检查支撑。失去有效支撑或触地丢失时，执行核心停止按旧接触集合求解支撑力。
- 控制器故障出口先清空可能只计算了一部分的输出，再构造既有阻尼命令。阻尼退出不是主动恢复，也不保证受扰后不倒地。
- WBC 计时允许测试时注入单调时钟函数；正式运行使用 `steady_clock`。不存在 ROS 请求修改反馈、接触或计时的生产接口。

新阈值均属于控制配置，与独立验收配置分开。原落点、姿态、足心位移门槛未放宽。

## 独立评价

`qr_simulation` 在每个 Gazebo 物理步计算接触点双方刚体的相对切向速度，按接触流形取平均后积分。评价器取动作前后的累计差：

- `support_foot_center_displacement_m`：支撑足心相对动作起点的最大位移。
- `support_contact_slip_m`：各支撑足接触点累计滑移中的最大值，门槛 10 mm。
- `support_slip_m`：旧足心位移字段的兼容别名，不能再解释为累计滑移。

理想纯滚动在第二项中为零；Gazebo 离散接触和刚性球足仍存在数值误差。真实软足底的接触斑形变未验证。

所有 `/evaluation/*` 数据只供评价。控制仍使用 IMU、关节及模型残差，没有新增足底传感器。每次记录展开 URDF、场景、控制配置和哈希；源指纹新增 `.def` 参数/枚举文件。

## 三类测试必须分开解读

1. **物理故障**：Gazebo 内生成侧壁或有限时间的外力。必须独立观察到侧碰、离地或累计滑移，服务返回成功本身不算注入有效。验证动作退出和不报成功，不认证恢复稳定性。
2. **控制边界故障**：C++ 执行核心接收冻结/乱序的关节或 IMU 采样；求解超时测试在实际 WBC 调用前后注入时间差。验证故障路由和锁存，不代表真实总线故障或主机最坏执行时间。
3. **有界模型扰动**：Gazebo 每个机器人链接的质量/惯量 ±5%，以及足端摩擦系数 0.35。质量在暂停物理时通过属性服务修改并回读，控制模型保持规范模型。不是传感噪声或全面域随机化。

## 失败记录

- 初版外力注入使用默认零开始时间，仿真时间已过去，未形成实际扰动；原始记录保留，不算故障通过。
- 初版侧壁使旧控制直到触地超时才退出；新增持续摆腿跟踪误差检测。
- 加入检测后，旧离线预检把摆腿的“测量位置”一直设成终点，导致正常计划被拒；改为理想跟踪上一离散参考，仍遍历完整参考轨迹。
- 高侧壁先碰到小腿，不能用来证明足端侧碰；改为摆腿中后段加入低侧壁，并要求足端碰撞名称见证。
- 直接修改发布 URDF 的质量触发规范模型校验；保留校验，改用 Gazebo 物理属性服务独立扰动。

本地失败日志在 `artifacts/rc2027/dynamic-*-v*`、`m1-closeout-faults-v1`、`m1-closeout-robustness-v1`，不覆盖旧结果。

## 复现

先按 QR README 构建并 source 工作区；输出目录须不存在。

```bash
python3 tools/validate_qr.py --suite regression --output artifacts/qr/closeout-regression
python3 tools/validate_qr.py --suite robustness --output artifacts/qr/closeout-robustness
python3 tools/validate_qr.py --suite matrix --output artifacts/qr/closeout-matrix
```

M1 仅针对已知平面、0/30/50 mm 平台的单腿换步。噪声与总线时延、完整自碰撞规划、趴姿起身、稳定恢复、NX、真机以及比赛障碍仍需后续验证。ThreadSanitizer 在本机启动失败，不能宣称无数据竞争或具备硬实时保证。
