# QR 模块化改造验证

[中文入口](README.md) | [English](README_EN.md) | [机器可读结果](refactoring-results.json)

日期：2026-10-09；开发分支 RC2027；改造基线 cc62849。

## 实现与范围

- 固定三缓冲代替控制线程上的尝试互斥锁发布；单写者，非实时读者取完整副本。
  快照的错误字符串改为数值枚举。交换路径有界不等于整体 WBC 硬实时。
- Runtime 40 行，组织 Planner / ExecutionCore / RosAdapter；两个算法组件无 ROS 接口依赖，
  预检与控制独占模型缓存。公共 RobotModel 不创建 NMPC 问题；公共接触类型不依赖 precision。
- 模型/控制/验收三类配置、范围与组合校验、URDF 足半径核对；阶段与错误数值码已加入接口。
- 统一入口覆盖依赖检查、CTest、Python 和仿真，报告保留失败，默认验收阈值未放宽。
- 配置化接触驻留后，预检显式要求检查到 DONE；故障状态不再将旧估计标为有效。

## 最终版本结果

8 个相关包构建成功。CTest：控制包 9/9、规划 1/1、场景 1/1、验证契约 1/1；
后两组共含 7 项 Python 测试。包含并发快照、读者占用期间写者继续、时间新鲜度、
非法配置、公共模型加载、错误码映射和较长接触驻留下的完整预检。

`tools/validate_qr.py --suite regression` 最终 22/22 个入口用例通过：

## 调试失败记录

- 首次编译发现拆分后日志引用局部变量的范围错误，修正后重新构建。
- `modular-regression-1`：单元检查通过，但 ROS `/clock` 交付与控制 update 时间微小偏差
  触发新加入的未来时间拒绝。9 个已完成单步失败后停止该批次，另一个进行中用例被中止，
  原记录保留。改用单调采集时间判断快照新鲜度，ROS 时间继续用于场景/消息。
- `modular-regression-2`：22/22；之后补齐可配置驻留的预检终态和故障估计有效位，再跑本页最终批次。
- ThreadSanitizer 已编译并尝试运行（含 no-PIE 版本），均在运行时初始化阶段报
  `unexpected memory mapping`。**没有产生线程竞争检测结论，不能记为通过。**
